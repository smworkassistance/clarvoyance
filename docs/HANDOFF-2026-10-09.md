## Machine note (same as the last 2 handoffs — still true)
1. Check `Get-CimInstance Win32_OperatingSystem | Select FreePhysicalMemory` before assuming a crash/hang is a code problem.
2. Don't trust a `| tail -N` pipe for live progress on `ops/verify.js` — it buffers until exit. Run in the background and read the output file, or use `Monitor`.
3. chrome-devtools MCP disconnected entirely partway through this session (connection timeouts) while Chrome's own raw debug port (`:9222`) stayed reachable the whole time — when the MCP bridge is down, drive Chrome directly via a small raw-CDP Node script (`ws` package, `http://127.0.0.1:9222/json/...`) rather than giving up on live verification. **To avoid touching the owner's own open tab**: use `PUT /json/new?<url>` (not `GET` — newer Chrome rejects that) to open a brand-new, separate tab in the same browser instance, and close it with `GET /json/close/<id>` when done.
